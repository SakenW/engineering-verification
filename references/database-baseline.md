# 数据库迁移整理的验证上限

- 用户要求“整理、合并、压缩、重建 baseline/rebaseline”时，默认交付是一个可审查的 fresh-database 候选，不是生产数据库采用或切换。
- 该阶段必要验证限于：完整盘点迁移拓扑和数据保留责任；确认候选单 root/head；冻结资源清单与 hash；在项目指定数据库版本上做一次旧线终态与新 fresh 候选的确定性等价门禁；运行相关聚焦测试和静态检查。
- 若冻结候选的相关字节、资源 hash、迁移拓扑和验收脚本未变，上述昂贵等价门禁的成功证据可复用；不得因文档、回执格式或无关控制面调整重复运行。
- 未经用户明确进入生产采用任务，不实现或验证：生产停写/连接栅栏、版本身份正反向切换、真实备份/PITR、发布签名与运维回执、SIGKILL/掉电/硬链接等极端崩溃窗口、生产 workflow/executor。
- 旧迁移线的保留、逻辑冻结或物理归档必须与 fresh 候选分开判断；只要仍有活跃库或受支持备份依赖旧线，就不得删除或改写旧迁移。
